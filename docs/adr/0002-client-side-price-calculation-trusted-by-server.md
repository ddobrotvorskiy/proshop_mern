# 0002 — Цены заказа вычисляются на клиенте и принимаются сервером без проверки

- **Status:** Accepted
- **Confidence:** HIGH — явно читается из кода двух файлов без какой-либо домысловой интерпретации

---

## Context

При оформлении заказа необходимо вычислить итоговую сумму: стоимость товаров, доставку и налог. Вычисление можно делать на клиенте (в браузере перед отправкой) или на сервере (после получения `orderItems`).

## Decision

Все расчёты выполняются **на клиенте** в `PlaceOrderScreen.js` (строки 22–35) и передаются в теле POST-запроса. Сервер принимает готовые числа без пересчёта:

```js
// frontend/src/screens/PlaceOrderScreen.js:26-35
cart.itemsPrice = addDecimals(
  cart.cartItems.reduce((acc, item) => acc + item.price * item.qty, 0)
)
cart.shippingPrice = addDecimals(cart.itemsPrice > 100 ? 0 : 100)
cart.taxPrice = addDecimals(Number((0.15 * cart.itemsPrice).toFixed(2)))
cart.totalPrice = (
  Number(cart.itemsPrice) + Number(cart.shippingPrice) + Number(cart.taxPrice)
).toFixed(2)
```

```js
// backend/controllers/orderController.js:8-16
const {
  orderItems, shippingAddress, paymentMethod,
  itemsPrice, taxPrice, shippingPrice, totalPrice,
} = req.body
// ... сразу используются для создания Order, без пересчёта
```

Бизнес-правила (налог 15%, бесплатная доставка от $100, фиксированная доставка $100) захардкожены только на клиенте и нигде не дублируются на сервере.

## Alternatives

| Вариант | Почему не выбран (инференция) |
|---|---|
| Серверный пересчёт по `orderItems` + `product._id` | Требует дополнительного `Product.findById` для каждой позиции в заказе; усложняет контроллер |
| Валидация через express-validator / Joi | Нет ни одного `import` из этих библиотек во всём проекте — не рассматривалось |
| Хранение ставки налога и порога доставки в БД или env | Нигде не используется; выбрана простота учебного проекта |

## Consequences

**Плюсы:**
- Простота: контроллер `addOrderItems` остаётся тонким (37 строк).
- Нет дополнительных запросов к БД при создании заказа для получения цен товаров.

**Минусы (security):**
- Аутентифицированный пользователь может вручную изменить тело запроса и передать произвольные значения `itemsPrice`, `taxPrice`, `totalPrice`. Сервер сохранит их без проверки. Заказ на $1000 можно оформить с `totalPrice: 0.01`.
- Бизнес-правила (15% налог, $100 порог) существуют только в одном месте — в компоненте React. Изменение логики ценообразования не отразится на уже созданных заказах и не защищено от обхода.
- `itemsPrice` принимается из `req.body`, но отсутствует в схеме `orderModel.js` как отдельное поле — Mongoose молча его игнорирует, и поле не сохраняется в документ, хотя контроллер передаёт его конструктору `Order`.
