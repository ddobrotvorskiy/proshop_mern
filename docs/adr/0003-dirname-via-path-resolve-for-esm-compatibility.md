# 0003 — `__dirname` заменён на `path.resolve()` для совместимости с ES modules

- **Status:** Accepted
- **Confidence:** MEDIUM — решение явно видно в коде (`backend/server.js:35`), мотивация инферируется из `"type": "module"` в `package.json`; явных комментариев нет

---

## Context

Бэкенд использует нативные ES modules (`"type": "module"` в `package.json:6`). В ES module-контексте глобальные переменные CommonJS `__dirname` и `__filename` недоступны — при обращении к ним выбрасывается `ReferenceError`. При этом в `server.js` нужно указать абсолютный путь до двух директорий:

1. `uploads/` — для раздачи загруженных файлов через `express.static` (строка 36)
2. `frontend/build/` — для ра��дачи SPA-бандла в production (строки 39–43)

## Decision

Вместо стандартного ESM-идиоматического способа получения пути к текущему файлу, была пр��менена однострочная замена:

```js
// backend/server.js:35
const __dirname = path.resolve()
```

`path.resolve()` без аргументов возвращает `process.cwd()` — текущий рабочий каталог процесса. Это работает корректно, потому что все npm-скрипты в `package.json` запускают сервер из корня репозитория, где и лежит `frontend/build/` и `uploads/`.

## Alternatives

| Вариант | Почему не выбран (инференция) |
|---|---|
| Стандартный ESM-идиом через `import.meta.url` | Более многословен (3 строки vs 1); разработчик явно отдал предпочтение краткости. AGENTS.md даже явно предписывает не добавлять `fileURLToPath`-вариант |
| Сохранение CommonJS (`"type": "commonjs"` или `.cjs`-расширения) | Противоречило бы выбору ES modules; весь импорт в бэкенде уже использует `import/export` |
| Не использовать `__dirname` — хранить пути относительно CWD явно | Функционально эквивалентно текущему решению, но требует изменения аргументов `path.join` |

Стандартный ESM-вариант, от которого отказались:

```js
// НЕ используется в проекте
import { fileURLToPath } from 'url'
const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)
```

## Consequences

**Плюсы:**
- Однострочное решение — минимальный cognitive overhead.
- Работает для всех случаев использования в проекте, пока сервер запускается из корня репозитория.

**Минусы:**
- Хрупкость при смене CWD: если сервер будет запущен командой `node backend/server.js` из директории `backend/`, `path.resolve()` вернёт `…/backend`, и пути к `frontend/build` и `uploads` сломаются. Это молчаливая ошибка — сервер запустится, но статика не будет отдаваться.
- Семантическое несоответствие: `__dirname` обычно означает "директория текущего файла", а `path.resolve()` возвращает "текущую рабочую директорию процесса" — это разные вещи в общем случае.
- Решение не переносимо: если `server.js` будет перемещён в поддиректорию или проект перейдёт на монорепо, код сломается без явной ошибки компиляции.
